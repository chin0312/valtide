## New material correctness findings

1. **Validation information set does not resemble the use case.** `research/model_suite/R/evaluation.R` calls `prepare_model_data(test_dt, hide_nvda=TRUE)` for the **entire validation period**, then saves `masked_fair_value`. `research/scripts/evaluate_v2_validation_and_freeze.py` uses that map for both overlap comparisons and reopening events. Thus the candidate never assimilates any July/August trusted underlying observation after the June training boundary, even while normal underlying bars exist. Live `P1aCRuntime.step()` assimilates current underlying after producing that tick's quote so it is available for the next tick. The v2 candidate's state grows stale for up to 46 days; raw xStock does not suffer that restriction. Masked-overlap is a legitimate *stress diagnostic* if labelled, but is not a fair primary measure of live, periodically anchored challenger performance. In a read-only calculation using the already saved P1a prediction files, replacing event `masked_fair_value` with saved `model_fair_value` lowers validation event MAE from 138.48 to 62.30 bps (NVDA), 72.42 to 14.78 (SPY), 139.21 to 68.92 (TSLA); raw event errors remain 43.06, 9.14, 59.93. This is **exploratory diagnostic evidence**, not a repaired experiment or proof of a winning challenger: the saved normal R filter assimilates same-timestamp underlying before reporting its state and needs a causal production-equivalent redesign. QQQ is 18.66 masked / 18.92 normal / 18.61 raw; AAPL 41.15 / 42.49 / 40.89.
2. **Extreme thin-volume training quotes dominate a Gaussian measurement model.** The panel admits any finite positive token close, regardless of volume or implausible one-bar jumps. NVDA has a 2026-04-29 19:10 UTC token close **$19,768.15** against underlying **$209.17**, on `0.000505` token volume; this single row contributes approximately **100%** of the training blend denominator `sum((token-stale)^2)`. SPY has a $318,839.39 candle on 2025-12-16, volume `0.001469`; TSLA has several roughly $1,600–$1,800 regular-session candles against ~$440 underlying on 2025-12-03/08. These are included unchanged. `state_space_models.R` fits a Gaussian log-price likelihood and bounds `logR_nvdax` at `-1`, so NVDA/SPY/TSLA P1a token variance hits `exp(-1)=0.367879` in **every session**. Underlying R is orders of magnitude smaller and overnight Q hits `exp(-25)`. The filter consequently discounts the token almost completely and retains a stale underlying level through the validation blackout. The learned blend also assigns NVDA `w≈0.000018`, SPY `w≈0.0335`, TSLA `w≈0.000272`, rather than representing the typical regular-session 1–4 bp token overlap. This is an implementation/data-quality problem interacting with a Gaussian model-specification mismatch, **not** evidence that those models intrinsically cannot use token price discovery. Any intervention must have an ex-ante source/microstructure rule and must retain the excluded rows for sensitivity analysis; clipping until a winner appears would be invalid.
3. **Opening comparison uses unequal anchor information.** `session_pairs()` calls the last *regular-session* underlying candle the last trusted close. Yet the panels contain later premarket/afterhours underlying bars, the learned blend uses the latest preceding underlying bar, and `model_fair_value` can assimilate them. In the final 24 opening events per asset, a later underlying exists before the selected token point in 21 NVDA, 24 SPY, 24 QQQ, 18 TSLA, 23 AAPL events. One NVDA example uses 2026-08-18 19:55 UTC `$219.73` as “stale” although a later premarket underlying price `$221.46` was available before the 2026-08-19 13:25 token candle. The opening proxy is an ex-post 15-minute RTH VWAP with two or more valid observations and a 5% anomaly check; all 24 final events per asset use that VWAP. But “regular” uses weekday/New York clock time, not an exchange holiday/half-day calendar or an observed liquid-session-quality floor. Define and compare equal-information baselines and an actual underlying-unavailable gap; preserve the RTH-to-RTH stress study separately.
4. **The 30-minute “fresh” gate applies to bar opening time, not independent market activity or confirmed availability.** All 24 final events per asset are marked fresh with token bar-open age 5 or 10 minutes. The last selected candle has **zero volume** in 24/24 NVDA, 23/24 SPY, 24/24 QQQ, 24/24 TSLA, 24/24 AAPL. Counting back to the last positive-volume candle yields only 3, 5, 2, 1, and 0 events, respectively, within 30 minutes; median positive-volume-candle ages are 100, 110, 240, 280, 640 minutes. Positive candle volume is only a trade-activity proxy until the provider data are reconciled to transactions. A close for a 13:25–13:30 candle is not known at 13:25; with `confirm=1`, it is usable only when completed and received. Fifteen of each asset's 24 selected final events have 5-minute bar-open age, so availability may coincide with or follow the reopening benchmark's start. These are causal and interpretation blockers. Investigate source-specific quote-vs-trade semantics and observed publication latency before choosing a pre-reopen cutoff.
5. **Freeze is content-consistent but not a pristine holdout.** R's development loader bounds rows at validation end, and all five freeze timestamps (2026-09-29 19:10–19:20 UTC) precede R/Python final-evaluator start markers (19:21 UTC). However, the builder computed full-cutoff price-overlap QA and full-cutoff raw/stale reopening benchmarks before freezing; the freeze files disclose this. The manifest currently on disk has `created_at_utc=19:29:47`, *after* the final run, although its current 45 file hashes match stored freeze digest. That supports present content integrity but the saved manifest timestamp alone does not prove the same file bytes were fixed before final access. The final evaluator compares freeze to metadata hash strings and manifest digest strings rather than recomputing source/code bytes at evaluation. No evidence here shows post-freeze tuning, but the final window cannot be described as wholly untouched.
6. **The NVDA parity test proves a narrower property.** `run_nvda_generic_legacy_parity.R` creates the “legacy” cache from the **same v2 generic data**, fixes P1a on both paths, and runs the same model code. Exact numerical equality is expected and useful for loader serialization, but it does not reproduce the original legacy dataset, select a model, or explain the old ~7 bps vs v2 ~154 bps difference. The old source cache is unavailable. The legacy P1a-C interval report compares calibration to Gaussian intervals, not P1a point accuracy against raw xStock. The preserved legacy P0–P5 comparison itself lists raw masked MAE ~5.16 legacy log-bps, below every challenger (~7.2–7.9).
7. **Decision semantics overstate final evidence.** With sufficiency marked PASS, `evaluate_v2_locked_final.py` maps `selected_structural_model=RAW_XSTOCK` directly to `RAW_XSTOCK_SUFFICIENT`. It never checks whether failed candidate fits were valid or whether candidate predictions were actually evaluated on final data. The final summary reports raw/stale/blend only; challenger final `n=0`, no paired final interval, no challenger calibration. `INSUFFICIENT_EVIDENCE` or a quarantined research decision is more faithful until the comparison is repaired. Baseline summary sample sets also differ (`stale` includes underlying rows without token, `raw` requires overlap); use paired samples for comparative claims.

The week-block bootstrap correctly pairs model minus raw absolute percentage-bps errors, resamples ISO-week **means**, and labels cumulative 60/240/480/960/1440-minute event thresholds. Its five to seven validation weeks and roughly 29–31 events per asset are small for tail/regime inference. Pyth has no historical point-in-time series in the supplied panels and was correctly omitted. P3 has no valid external point-in-time factors and was correctly skipped. Quality features in P4/P5 are lagged in the R loader; their conditional-R/AR-basis variants cannot rescue the poisoned shared likelihood and misaligned evaluation.

## Why P0–P5 lost: classified causes

| Mechanism | Finding | Classification |
|---|---|---|
| Normalization scale | Identity direct-token scale fits overlap; v1 `/multiplier` caused artificial ETF/Apple offsets | v1 implementation bug repaired in v2 |
| Token measurement noise | Sparse, extreme training candles drive log-Gaussian token R to upper boundary for NVDA/SPY/TSLA | Data-quality failure + model specification mismatch |
| Training objective | Full-grid Gaussian log likelihood is dominated by magnitude-heavy outliers and many underlying measurements; not optimized for paired reopening or robust errors | Model specification mismatch |
| Filter/measurement equation | One-state P0/P1a/P1b treats both prices as observations of same log state; P2–P5 add partial adjustment/basis/quality but inherit poisoned training. P2's lagged-state measurement and P5 basis have no demonstrated rescue | Unvalidated structural assumptions |
| Validation state path | Hides **all** validation underlying observations, unlike warmed live filter | Experiment implementation bug |
| Initialization/warm-up | State starts from first training observation and enters validation at final training state; 46-day no-anchor masked path creates long drift/lag | Experiment design mismatch, magnified by low Q / high R |
| Q/R and regimes | NVDA/SPY/TSLA token R saturates at 0.367879, underlier R near zero, overnight Q often at floor. Session labels rely on clock, not official trading calendar | Boundary diagnostics confirm model unreliability |
| QQQ/AAPL near parity | P0/P2 differ from raw by only ~0.07–0.11 bps for some overlap tests; added complexity has not earned its cost | Plausible expected economic result, **not** universal refutation |
| Validation asset activity | Positive-volume fraction falls sharply from training to validation/final; very few final fresh-trade reopening observations | Insufficient information for the claimed off-hours market-discovery/use-case inference |

The actual result combines these causes. It would be as wrong to declare “the model can never work” as to declare “the model definitely works after an outlier fix.” Current evidence shows no demonstrated incremental value. Repaired same-asset development analysis remains **exploratory**, because the v2 final period and results have already been seen.

## Product hypotheses and competitive test

**H1 — tokenized-market price discovery: suggestive but unvalidated for closures.** The raw OKX field is closer than the last RTH close to the 15-minute reopening proxy in the reported sample, but the last candle is almost always zero volume and 15 of 24 final events per asset use a candle that only finishes at the reopening boundary. The result may describe a derived indicative feed rather than an independently traded off-hours market. The claim requires source/trade provenance, causal availability, and equal-information stale baseline.

**H2 — challenger incremental information: unsupported.** All six evaluated model structures failed frozen validation selection. V2's measurement and information-set problems prevent treating this as a clean refutation of the whole family. There is no selected challenger, calibrated v2 interval, or final paired challenger-vs-raw result. The prior P1a-C ~7 bps legacy report does not supply an incremental raw comparison on equivalent observations.

**H3 — reference-validation differentiation: plausible use case, not yet proven advantage.** Valtide can keep a reference under test separate from evidence sources, record provenance, compare multiple genuinely independent references, abstain on stale/missing/degraded inputs, and expose uncertainty/disagreement. The live backend currently drives `SUPPORTED/INCONCLUSIVE/CHALLENGED` from a P1a-C reference-predictive interval plus quality gates; its liquidity gate defaults to zero, so a near-dead DEX pool is not filtered by that guard. The research has not measured false-challenge rates, useful interventions, or superiority to a well-designed conventional risk monitor. If the “challenger” simply republishes the same xStock feed, it is not independent of that market or of a reference derived from it. Independence must be assessed against the *specific reference under test* and upstream source lineage.

**H4 — Evidence → policy → enforcement: working separation, partial differentiation.** `ValtideValidationRegistry` stores `(assetId, referenceId)` attestations and provenance hashes; `ValtideRiskGuard` evaluates a consumer-owned mapping and staleness; `DemoCollateralVault` applies it. Backend owns evidence and browser is read-only. This is a coherent composable prototype on X Layer testnet, but a protocol could implement xStock consumption plus ordinary oracle monitoring and risk controls itself. [Chainlink's consumer guidance](https://docs.chain.link/data-feeds/overview) already recommends monitoring and safeguards; [Aave's oracle documentation](https://www.aave.com/docs/ecosystem/oracle) covers governance-selected feeds and [Horizon](https://www.aave.com/docs/aave-v3/horizon) uses oracle-level RWA bounds. xStocks' own [wrapper guidance](https://docs.xstocks.fi/developers/wrapped-xstocks) calls for independent prices, staleness and deviation checks. The architecture's separation is useful and demonstrable, but not unique. A defensible independent service would need evidence that its cross-source provenance, failure detection, calibrations, policy integrations, and response time beat a conventional implementation on real incidents and false alarms. No such comparative evidence is present.

**Direct product answer:** if no challenger ever beats raw xStock, Valtide is a reference-quality attestation and policy-adapter service, provided it uses independent sources to identify when that xStock/reference itself is unreliable. A protocol can build this from xStock plus a conventional oracle/risk-monitor; current repository evidence does not show a hard-to-replicate information advantage. It can be pitched as an auditable control integration prototype, not a proven superior valuation engine or unique risk-control category.
